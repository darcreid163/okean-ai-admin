# WP AI Admin 2.0.56 — кандидат для проверки

Дата: 28.09.2026. Исходная установленная версия 2.0.55 прошла self-test 49/49, Security Fuzz 200/200 и Regression Matrix 90/90 за две итерации с восстановлением baseline. Эти показатели **не являются результатами 2.0.56**, пока кандидат не установлен.

## Изменение

Все мутации batch job (`create`, `resume`, `pause`, `retry`, `cancel`, `rollback`) выполняются под одним именованным MySQL lock, привязанным к базе и префиксу таблиц WordPress. Конкурирующий запрос возвращает 409, если lock занят; при недоступности блокировки возвращает 503. Lock освобождается в `finally` и также освобождается сервером при закрытии соединения. Прежняя 60-секундная lease остаётся в checkpoint для наблюдения за job.

Batch jobs хранятся в общем WordPress option, поэтому блокировка охватывает мутации разных jobs и исключает потерю изменений при двух одновременных read/modify/write. Цена — последовательное выполнение batch-мутаций на одной установке.

## Ворота проверки

- PHP lint 58 файлов (57 файлов плагина и один тест) на PHP 8.2, 8.3 и 8.4.
- ZIP integrity.
- Два независимых PHP-процесса против одного MySQL: первый удерживает lock, второй получает `oai_batch_busy`, следующий после release входит.
- После установки: catalog 90/90, self-test 49/49, повтор двух resume одного job, Regression Matrix 90/90 с `baseline_restored=true`.

CI проверяет реальную конкуренцию за MySQL lock, но не заменяет полный сетевой тест двух WordPress/PHP запросов на хостинге. Прямые live writes по-прежнему запрещены; запись batch создаёт только sandbox child-operation.
